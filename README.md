# 스터디온 · 9주차

일과 공부를 병행하는 학생이 과목과 목표, 학습 시간을 정하고 다시 확인하는 서비스다. 기존 계획 만들기와 보관함을 이어서 수정했다.

## 이번에 바꾼 점

입력칸마다 도움말과 오류 안내를 붙였다. 과제 마감일이 필요한 경우에만 날짜를 입력하게 했고, 내용 확인 후 저장하는 과정도 폼 제출로 처리했다.

- 마감일 기록을 선택하면 날짜 입력칸이 나타나고 사용할 수 있다. 선택을 해제하면 숨기고 `disabled`로 바꾼다. 해제한 날짜는 저장하지 않는다.
- 입력 중 목표 글자 수를 보여준다. 오류는 해당 항목 아래에 표시하고 올바르게 고치면 해제한다.
- 저장 중에는 진행 문구를 표시하고 저장·수정 버튼을 잠근다. 저장이 끝나면 보관함에서 다시 열 수 있다.
- 같은 계획을 다시 저장하면 중복으로 추가하지 않는다. 다시 시작하면 입력과 안내를 초기화하고 이미 보관한 계획은 남긴다.

## 입력 조건

과목은 앞뒤 공백을 제외한 2~60자, 목표는 10~300자로 작성한다. 하루 시간은 20·40·60분 중 고른다. 마감일 기록을 선택했다면 오늘 또는 이후 날짜가 필요하다. 이메일은 선택 사항이며 입력했을 때만 형식을 검사한다.

## 확인 순서와 결과

2026년 11월 6일 브라우저에서 다음 순서로 확인했다.

1. 학습 계획 시작 → 빈 상태로 다음 버튼을 눌렀다. 입력 화면에 머물고 과목·목표·시간 오류가 표시됐다.
2. 짧은 목표와 잘못된 이메일, 과거 마감일을 넣었다. 각각 오류가 표시됐고 올바르게 고치면 오류 표시가 사라졌다.
3. 마감일 선택을 켰다 껐다. 입력칸 표시와 비활성화가 함께 바뀌고, 다시 켜면 작성한 날짜가 유지됐다.
4. 목표와 40분, 마감일을 입력해 확인 화면으로 갔다. 주 5일 200분과 날짜가 반영됐다. 저장 중 버튼이 잠겼고, 저장 후 상세에서도 같은 내용을 확인했다.
5. 새 계획으로 다시 시작했다. 입력과 체크박스·안내 문구가 초기화됐고 보관한 계획은 유지됐다.

저장은 이 브라우저의 `localStorage`를 사용한다. 저장소를 읽지 못하거나 용량이 부족하면 `script.js`의 `loadPlans()`·`persistPlans()`가 실패를 반환하고, `submitPlan()`의 `catch`에서 입력을 유지한 채 다시 저장하도록 안내한다. 저장 실패 자체는 이번 브라우저에서 강제로 재현하지 않았다.
